# Findings tables

Produced by `python -I scripts/13_findings_tables.py`. Descriptive only: no tests, no funding comparison. Rerun after each data refresh; the files are overwritten.

## Sample (all tables)
- DPGs with `dpg_confidence == "high"` in `data/dpg_confidence.csv`.
- Numbers come from `data/dpg_quarterly.csv`, which is built on the fixed cohort of repos (D21/D45: repo created before 2024, or at least 50 commits before 2024). New repos from 2024 on are not counted.
- The current partial quarter (flag `partial_quarter`) is dropped. The last year may therefore have fewer than four quarters; see `n_quarters`.
- The panel is unbalanced: a DPG appears from the quarter its first cohort repo exists, so the number of DPGs rises over 2020-2023. `n_dpgs` is the number of distinct DPGs in the row; `n_dpg_quarters` is DPG-quarters. In year tables, shares and medians are taken over DPG-quarters, not over DPG-years.
- DPGs with no cohort repo have no rows and are not in any table.

## Balanced and unbalanced versions
- Tables without a suffix are **unbalanced**: every high-confidence DPG with rows in that quarter, so the set of DPGs changes over time (DPGs enter when their first cohort repo exists).
- Files with suffix `_balanced` (tables 1, 2, 3) use a **balanced panel**: the 100 DPGs (on full data; 85 on the earlier partial data) that have panel rows in every complete quarter from 2021Q1 to 2026Q3 (>= 60, so the 2021Q1 start is used; no 2022Q1 variant needed). Same DPGs in every period, so changes cannot come from DPGs entering. The number is printed on every run (`BALANCED SET`). It is a subset of long-lived projects.
- Table 2 (unbalanced) also carries `same_dpgs_*` columns: the balanced-set ratios next to the unbalanced ones (blank for 2020).

## Tables
- **t1_core_by_quarter / t1_core_by_year.** Core contributors = people active in at least 2 of the 3 months of a quarter, de-duplicated across the DPG's repos, bots excluded (D39). Columns: total across DPGs (`core_total`), median per DPG, share of DPGs with 0, 1-2 and 3+ core contributors, plus total active contributors and total reviewers for the wider circle. In the year table the totals are sums of four quarterly counts (person-quarters), not distinct people.
- **t2_output_per_core_by_quarter / _by_year.** Output per core contributor as a ratio of totals: sum of output over sum of core contributors in the period, never an average of per-DPG ratios. Output A (primary) = minor releases + major releases + issues closed. Output B = human merged PRs (bots and AI agent PRs excluded), shown separately. Output C = all releases (`release_total`) + issues closed, shown next to A. Columns `unclassified_releases` and `unclassified_share` give the releases that are in the total but not in major/minor/patch (see below).
- **t3_*_by_age_*.** Tables 1 and 2 repeated for two groups defined by the creation date of each DPG's oldest cohort repo: `created_before_2018` and `created_2018_2023`. If a pattern shows only in the older group, it points to ageing rather than a period effect. DPGs without a usable creation date are left out of this table.
- **t4_releases_by_year.** Per year: total releases, number of DPGs that released, median releases per releasing DPG (per DPG-year), and the major / minor / patch counts. `unclassified_releases` and `unclassified_share` = total minus major/minor/patch. In `03_aggregate.py` (`release_kinds`), every GitHub Release (or, for repos with no Releases, every git tag: the "tag fallback") whose name contains a number like `1.2` or `1.2.3` is classed against the highest version seen so far; the first one is `first`, and a version at or below the highest so far is `backport`, so unclassified releases are exactly `release_first` + `release_backport`. Tags with no `x.y` number (date-based or other names) and pre-releases are not counted at all, and tag-based repos produce most of the unclassified ones (about 75-90% of their releases, against about 7-12% for repos using GitHub Releases), because tags are dated by commit and often arrive out of order. `t4_releases_by_year_and_method` repeats the split by `release_method` (`releases` or `tags`, a repo-level field), over the cohort repos of the sample.
- **t5_roles_review_by_year.** Only DPG-quarters with at least one human merged PR. Median authors, reviewers and mergers per DPG-quarter. `pooled_review_coverage` = merged PRs reviewed before merge / merged PRs, summed over all rows. `pooled_self_merge_unreviewed` = PRs merged by their own author with no review / merged PRs.

- **t6_first_time_contributors_by_year / _by_quarter (+ `_balanced`).** From `data/people_quarterly.csv` (hashed person id, already de-duplicated within a DPG, bots excluded). A person's first quarter in a DPG is the earliest quarter they appear for that DPG; they count once as a first-timer there. Columns: first-timers, first-timers per DPG in the panel that period, active people that period (distinct people per DPG, so someone in two DPGs counts twice), the share of active people who are first-timers, and the first role: `code_author` (commit or PR author), `merger` (merges but no code) or `reviewer_only`. Retention = share of first-timers active in the same DPG again in any of the next 4 quarters; `share_ever_core_later` = share who are core in any later quarter (the first quarter does not count). **Burn-in:** data start in 2020Q1, so everyone active in 2020 looks new, including long-standing contributors; 2020 rows are flagged `burn_in_2020` (2020 share of first-timers is 1.0 by construction) and trend columns should start in 2021. **Censoring:** retention and core need a full 4-quarter follow-up window, so a cohort is evaluable only if its first quarter is at least 4 complete quarters before the last complete quarter. `n_evaluable_for_followup` counts those; shares are computed only on them, and `followup_status` says `complete`, `partly_censored` or `censored` (shares blank, not zero). The balanced version restricts to the balanced DPG set and periods from the balanced start, but first quarters are still found in the full history. First-timers are new to that DPG, not new to open source.

## Limits
Squash merges credit only the PR author; work moved to private repos or other platforms looks like a drop; non-code staff are invisible; survivorship (only DPGs listed today) applies throughout (D22, D40).
